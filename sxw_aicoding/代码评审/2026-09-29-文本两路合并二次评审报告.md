## 三、重点排查的隐藏风险（均未发现问题）

1. **Worker 会不会导致同步占用无法释放？**`mergeText` 的所有结算路径（结果、异常、提前退出、超时、取消）都经过 `finish`，先 `await worker.terminate()` 再 resolve / reject。墙钟计时器保证 Promise 一定会结算；`terminate()` 能中断同步 JS 计算；计时器在事件监听挂上之前就已初始化，不存在 TDZ 问题。预检查并发、上传扫描、网络请求也都有上界，没有找到会让 `run()` 永不结束的路径。
2. **Worker 数据是否会损坏缓存？**`workerData` 走结构化克隆，没有使用 transferList，因此缓存里的 Buffer 不会被 detach；池化小 Buffer 的 byteOffset 由 `Buffer.from(view)` 正确处理。已用真实数据验证输出逐字节不变。
3. **新扫描器会不会漏报，导致带标记的文件被上传？**以旧实现的整行语义为基准做差分测试：随机组合三种标记、「（」附注、BOM、`\r` / `\n` / `\r\n`、中文和近似文本，每例分别用整串，以及 1 / 2 / 3 / 7 / 33 / 34 字节和随机分块推送。回看窗口是 33 字节，33 和 34 正好卡在边界上。结果：**200,000 例，其中 31,832 例含标记，0 例不一致**。按字节推导，回看窗口足以覆盖「前一字节 + BOM + 最长标记 + 附注首字符」，与测试结果一致。
4. **并发预检查的共享状态**：`next++` 取任务、`checks` / `summary` / `cache` 的读写都在单线程事件循环里完成；`DiffDirectoryIndex` 原本就为 Diff 的 3 路并发设计了并发未命中处理。取消时每个 worker 在当前读取结束后退出，`allSettled` 汇总后统一抛出。
5. **原位替换会不会吞掉错误，让任务误报成功？**同一个 key 在执行阶段最多产生一条非 cleanup 记录；替换只会把 `check` 变成 `error` / `skip` / `merge`。「是否有 error」的判定不会因替换而丢失，cleanup 记录不参与替换。

## 四、剩余观察项（非阻塞）

1. **（低中 · 体验）详情面板打开时，每次记录变化都会退回第 1 页**。`syncSlice.ts:21-25` 在 `issueRevision` 变化时清空列表，`SyncPanel.tsx:39` 随即重新加载前 50 条。同步进行中每个文件都可能推动 revision，用户点「加载更多」得到的后续页面会被反复清掉，列表还会短暂闪空。任务结束后恢复稳定，属于数据一致性和浏览体验之间的取舍。**建议**：重载时保留已加载的条数（按原长度分页拉回），或在任务进行中降低自动重载频率。
2. **（低）致命错误会顶掉当前文件的检查记录**。任务级致命错误用 `currentFile` 作为 path 记录（`sync.ts:532`），而 `issue()` 对非 cleanup 记录按 path 原位替换（`sync.ts:237`）。例如预检查结束后 `checkRoot()` 失败时，最后一个被检查的文件的检查记录会被根目录错误覆盖，错误也会显示在这个文件名下。原本「错误挂在 currentFile 上」的归属问题就存在，这次改为覆盖后，还会丢掉该文件的检查结论。**建议**：任务级错误不参与按 path 替换（例如 path 置空或单独标记）。
3. **（低 · 加固）Worker 未设置 `resourceLimits`**（`textMerge.ts:47`）。5 秒墙钟和 jsdiff 的 timeout 已经限制了计算时间，但病态输入在 5 秒内的内存增长没有上限。可以考虑设置 `maxOldGenerationSizeMb`：超限时 Worker 以 error 退出，当前路径会把它当作该文件失败处理。
4. **（低 · 能力边界）整份重写的文件会超出 CPU 预算**。没有共同行的大文件（例如 2 万行对 2 万行）在 Myers 算法下超时跳过，这种情况合并出来的结果也只是一个整文件差异块。可选的优化是：没有共同行时直接输出单块，跳过 diff 计算。当前行为符合方案。
5. **（提示）冒烟测试的偶发超时尚未定位**。修复说明记录过一次「后续 Diff 阶段总超时」。按本次分析，同步任务不存在无上界的等待，而那次超时发生在 Diff 阶段，该阶段输入在本轮从 2 MB 提升到 5 MB（5 MB 单行、6.5 万行），因此更可能是 Monaco 大输入耗时接近 240 秒总时限，而不是同步占用泄漏。**建议**：连续跑几次 `test:electron`，记录新增的 Diff 分段日志耗时，确认离总时限还有多少余量。
6. **（已知取舍）P5**：同步目录里只要有一个未变化的超过 5 MB 的文本，每次「同步到本地」都会弹窗；合并模式下相同的非文本文件记为跳过。修复说明已明确保留，这里仅留档。
