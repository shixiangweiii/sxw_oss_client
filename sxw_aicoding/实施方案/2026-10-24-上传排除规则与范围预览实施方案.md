# 上传排除规则与范围预览实施方案

日期：2026-10-24。基线：`f9c944e`。依据本次最新讨论，按个人使用、手动触发同步的范围实施。

## 产品约定

1. 从开发环境 `.env` 读取 `sync_ignore`，英文逗号分隔，去除两端空白及空项。刷新配置或重启后生效。未配置或为空保持原上传范围。
2. 只影响“同步到云端”。无路径的规则匹配任意层级同名项；有路径的规则从同步根目录匹配；前导 `/` 可显式限定根目录；尾部 `/` 只匹配目录。支持 `*`、`?` 和独立路径分量 `**`，大小写敏感、包含隐藏名称，其余字符按字面匹配。不读取 `.gitignore` 内容，不提供取反规则或逗号转义。
3. 命中目录时剪枝，不遍历子树，也不上传目录标记；仅排除上传，不删除云端已有对象。名称 `.git` 不误匹配 `.github`。普通同步保留空目录，只有被排除内容的非空目录不额外生成空目录标记。
4. 点击上传后复用现有扫描，排除配置命中项及已知无法同步的项。预览展示完整候选范围，包含路径、大小、文件数、空目录数和候选文件总大小；每页 100 项，全部可翻页查看。
5. 标题为“确认同步到云端”，说明内容相同会在执行时跳过。提供普通“确认同步到云端”和“一键同步全部”：普通模式云端较新仍逐文件确认；一键模式一次性授权本轮候选范围内的覆盖，不再比较修改时间或逐文件询问，保留过滤、相同内容跳过和原同步传输检查。模式不跨任务持久化。预览并不提前读取文件正文或判断实际传输数量。
6. 取消、关闭预览、Esc 均取消；确认后按已扫描列表进入原有同步逻辑。确认前不得 PUT、初始化分片或写云端目录对象。没有候选项时直接显示“没有可同步的文件”，原有扫描问题仍记录在详情。
7. 预览期间占用现有同步互斥，其他窗口显示等待状态，只有发起窗口能查看及确认预览；取消、关闭、退出、刷新继续复用现有保护。仅增加确认生命周期所需状态，不增加文件监听、预览版本跟踪或确认后的重扫，原同步检查保持不变。

## 实施结构

- 新增纯业务模块 `src/main/syncIgnore.ts`，负责配置拆分和上述 glob 子集匹配，不增加运行时依赖。
- `oss.ts` 将规则随窗口配置快照传入任务；`sync.ts` 在本地扫描剪枝，按原冲突检查生成候选列表，调用上传确认回调，再执行原循环。
- 新增 `previewing` 活跃状态，以及上传预览分页读取、确认两条 IPC；同步状态继续全窗口广播，预览数据和决定绑定发起窗口及任务。
- 新增应用内 `UploadPreview` 对话框，使用原生 HTML dialog 的模态焦点及 Esc 事件，提供分页、取消、普通确认和一键同步。只传递轻量路径/大小信息，不在状态广播中复制整份列表。`uploadMode` 记录本轮选择，一键模式在既有修改时间确认入口直接通过；不会跳过内容比较或扩大候选范围。
- 更新 README 的行为说明，保留原有同步、Diff 和编辑规则。

## 验证计划
