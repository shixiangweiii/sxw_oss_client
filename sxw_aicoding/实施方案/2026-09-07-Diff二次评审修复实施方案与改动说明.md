## 二、实现设计

### 1. Monaco 初始化失败清理

- 提取独立的编辑器会话初始化函数，接收 Monaco editor API 与 DOM 容器；模块只使用 Monaco 类型，便于在 Node 中做边界故障注入。
- 按初始化进度持有编辑器、两侧模型、差异订阅和 viewModel。初始化成功返回编辑器与幂等 dispose；失败时立即清理已经成功返回的资源，再将原始错误交给 Error Boundary。
- 清理先停止状态回调与订阅，再释放编辑器、viewModel、文本模型；单个 dispose 抛错也必须继续尝试其他资源，清理异常明确记录，保留原始初始化错误。
- React effect 保持负责挂载/卸载；不把有 DOM 依赖的初始化移到模块顶层或渲染阶段。

### 2. 目录名称索引

- 新增扫描内共享的目录索引，精确名称使用 Set，Unicode NFD 和大小写折叠名称使用 Map，保持原有精确名称优先及别名判定规则。
- 每次路径解析仍实时 lstat 根目录及各个路径分量。缓存条目绑定目录的 dev、ino、size、mtimeNs、ctimeNs；目录状态变化时重读名称，重读前后不一致则报错。
- 配对阶段和三个比较 worker 共享索引；扫描结束、取消或失败时清空。单文件详情重读使用新的索引，只在这一次读取的前后校验中复用。
- 使用 LRU 限制最多 256 个目录、通常最多 100,000 个名称；一个超大目录允许独占缓存，避免因超过额度再次退化为逐文件重读整个目录。
- 不缓存本地文件正文，不降低 O_NOFOLLOW、文件句柄前后 stat 或云端版本/长度校验。

### 3. 分页排序缓存

- 用内部结果集合封装 Map 与排序快照。第一次分页时排序，后续分页直接切片。
- set（包括同 key 元信息更新）和成功 delete 均使快照失效；差异与问题集合分别缓存。
- 排序仍按当前 key 比较规则，不能依赖三个并发 worker 的完成顺序。重新扫描产生全新集合，结束会话释放集合。
- IPC 方法、返回结构和每页 100 条的约定不变。

### 4. 忙态与状态卫生

- openDiffFile 在同步活跃、同步启动等待或 Diff 启停等待时提示并返回，保持当前详情。
- 全局 Diff busy 且没有当前详情自己的 loading 请求时提前提示；存在自己的 loading 请求时继续原有“取消旧请求 → 检查请求代次 → 发起新读取”流程。
- 主进程 reserveDiff 仍是最终互斥边界，前端检查不替代原子占用。
- closeDiff 清空列表时同时将 diffPage 归零；合并同源 import type。

## 四、验收条件

- 初始化失败后显示错误兜底界面；编辑器、模型和订阅无残留，修正故障后能重新打开。
- 正常卸载与重复 dispose 安全；清理中的单个异常不会跳过剩余资源。
- 同一未变化目录只构建一次名称索引；新增/删除/重命名、根目录或目录替换、符号链接与别名冲突仍被识别。
- 连续翻页不重复全量排序；并发乱序、同数量替换、元信息更新、移除和恢复条目后分页结果正确。
- 全局忙态前置检查不会破坏自身详情请求取消、快速切换、重新读取或旧响应保护。
- 2 MB、Range 的额外字节检测、只读边界、窗口归属、原有同步和文本编辑功能通过回归。

## 五、实际改动与验证结果

已完成上述全部修复，并保留范围表中明确不调整的行为。

### 实际改动

- `diffEditorSession.ts` 统一负责编辑器、模型、订阅和 viewModel 的创建与清理。初始化异常先回收资源再向 Error Boundary 抛出；清理幂等，单个清理异常不阻断其他资源。
- `DiffDirectoryIndex` 为目录精确名称、NFD 名称和大小写折叠名称建立索引，绑定实时目录 stat 失效，提供 LRU 淘汰及扫描结束清空。配对与三个比较 worker 共享索引，单文件重读使用新的读取内索引。
- `DiffResults` 同时用于差异和未比较详情集合，连续翻页复用排序结果；元信息更新、增删、同数量替换和条目恢复均触发失效。
- `openDiffFile` 在外部占用时先提示并保留当前详情；自身 loading 请求仍可取消后切换。关闭整个 Diff 会话会重置页码；同源类型 import 已合并。
- 新增初始化与排序缓存测试，扩展目录索引和状态测试；真实 Electron 增加五种初始化故障注入。测试日志监听同步采用当前 Electron 的事件对象，消除了旧参数弃用提示。
- README 已补充异常恢复、忙态处理和缓存边界。原评审报告未修改。
