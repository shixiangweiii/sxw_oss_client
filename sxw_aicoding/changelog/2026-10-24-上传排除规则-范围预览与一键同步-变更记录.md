## 1. 背景与目标

原有“同步到云端”会递归扫描本地同步目录，随后逐文件比较和上传；没有可配置的上传排除规则，也没有整次上传范围的预览。个人工作目录中的 Git 元数据、IDE 配置和系统隐藏文件会进入同步范围。虽然云端较新的对象已有逐文件覆盖确认，用户仍缺少上传前核对整个范围的入口。

本次增加三个相互衔接的能力：

1. 从开发环境 `.env` 的 `sync_ignore` 读取文件／目录排除规则。
2. 在写入云端前展示过滤后的完整候选范围，由用户确认或取消。
3. 同时提供普通同步和“一键同步全部”：后者一次性授权本轮范围内的覆盖，省去逐文件确认。

使用背景是单人、手动触发的个人工作工具。范围预览复用已有扫描结果，不增加预览停留期间的文件监听、独立版本跟踪或确认后的重新扫描；原同步器已有的路径检查、上传快照和取消收尾继续保留。

## 2. 最终行为与方案决策

### 2.1 上传排除规则

配置示例：

```dotenv
sync_ignore=.git,.gitignore,.DS_Store,.idea
```

规则以英文逗号分隔，去除每项两端空白和空项并去重。未配置或为空时不增加排除项。规则跟随当前窗口的连接配置，刷新配置或重启后生效。

| 规则                 | 最终语义                                       | 评审关注点                                                            |
| -------------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| `.git`、`.DS_Store`  | 匹配任意层级的完整文件／目录名称               | `.git` 不匹配 `.github`，也能匹配 worktree 场景中的 `.git` 普通文件。 |
| `*.log`、`file?.txt` | `*` 匹配一个名称内的任意字符，`?` 匹配一个字符 | 包括隐藏名称；通配符不跨越 `/`。                                      |
| `docs/private/**`    | 从同步根目录匹配 private 目录及其后代          | 可以直接剪枝目录，但不排除恰好名为 `docs/private` 的普通文件。        |
| `docs/**/temp?.txt`  | 独立路径分量 `**` 匹配零层或多层路径           | `docs/temp1.txt` 和 `docs/a/temp1.txt` 均可匹配。                     |
| `build/`             | 匹配任意层级名为 build 的目录                  | 不匹配同名普通文件。                                                  |
| `/build/`            | 仅匹配同步根目录下的 build 目录                | 前导 `/` 表示根限定。                                                 |

匹配区分大小写；包含路径的规则相对于 `sync_dir_local`，路径分隔符使用 `/`。不读取 `.gitignore` 文件内容；配置中的 `.gitignore` 只是文件名称。字符组、花括号扩展、取反和逗号转义不属于本次语法，其他字符按字面匹配。空路径分量、`.`、`..` 或 NUL 等无效路径规则会明确报错，上传任务失败，不静默忽略该规则。

命中目录后停止遍历整个子树，不上传目录对象。命中项直接从扫描结果中剔除，不计入本次总数、已跳过或失败计数；不会枚举忽略子树来统计内部文件数量。规则只影响上传，不影响下载、文本合并、Diff 或在线编辑，不删除云端已有对象。

### 2.2 上传范围预览

最终流程：

```text
点击“同步到云端”
  → 运行既有恢复及目录准备，列举云端对象
  → 扫描本地，应用 sync_ignore 并对命中目录剪枝
  → 复用本地卷规则和名称冲突检查，生成候选列表
  → 无候选：直接提示；有候选：进入 previewing 等待决定
  → 取消 / 普通确认 / 一键同步全部
  → 确认后复用扫描列表，进入原有比较和上传循环
```

预览显示目标 Bucket、本地根目录、候选文件数量、候选文件总大小、空目录数量，以及每项的相对路径和大小。列表每页 100 项，全部条目可翻页访问；空目录显示为目录条目。仅含排除内容的非空目录不会被转换成空目录标记。

预览是**候选范围**：没有提前读取文件正文或进行 SHA-256 内容比较。相同内容仍在执行时跳过，因此预览的数量、大小不能标为实际上传数量或流量。已知名称冲突、符号链接等无法同步项不进入候选列表，执行原循环时仍记录跳过／失败详情；因此任务处理总数和候选列表数量可能不同。

上传任务在确认前不执行 PUT、不创建云端目录对象、不初始化分片。预览前仍有云端列举，以及既有的本地残留恢复和卷规则探测，不能将该阶段描述为完全没有网络请求或本地临时操作。

### 2.3 两种确认方式

| 操作／情况                                             | 普通“确认同步到云端”       | “一键同步全部”                         |
| ------------------------------------------------------ | -------------------------- | -------------------------------------- |
| 本地独有候选文件                                       | 上传新增                   | 上传新增                               |
| 两端内容相同                                           | 自动跳过                   | 自动跳过                               |
| 内容不同，云端较旧或同秒                               | 上传覆盖                   | 上传覆盖                               |
| 内容不同，云端较新                                     | 沿用原生逐文件覆盖确认     | 直接覆盖，不再逐文件询问               |
| 修改时间不可用                                         | 保留原有时间校验与失败处理 | 不依赖修改时间作覆盖决定               |
| 排除规则、路径／类型检查、上传快照、未整理合并标记拦截 | 保留                       | 保留                                   |
| 下一次上传任务                                         | 重新展示预览并选择         | 重新展示预览并选择，不延续本轮一键模式 |

“一键同步全部”授权的是**本轮候选范围中的覆盖**。它不扩大过滤后的范围，不关闭内容比较，也不绕过既有传输校验。界面明确说明包含覆盖较新的云端文件，任务面板记录本轮一键模式。

取消按钮、关闭预览和 Esc 均取消。对话框打开后显式聚焦“取消”按钮。没有候选项时不展示空确认框，任务面板提示“没有可同步的文件”；若扫描发现问题，仍可查看详情。

### 2.4 关键决策及理由

| 决策                                   | 理由与影响                                                                                                      |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 使用候选范围预览，不新增精确上传预检查 | 主要需求是核对上传范围及排除结果。沿用执行阶段的内容比较，避免重复下载／哈希，以及新增上传计划管理。            |
| 在本地扫描阶段排除                     | `.git`、`.idea` 等目录不再被完整遍历，其中文件也不会进入正文读取、快照、覆盖确认或上传。                        |
| 实现明确的 glob 子集，不新增依赖       | 当前所需规则可由名称匹配和路径分量处理完成；语法边界写入 README，避免宣称兼容完整 Git ignore 或其他 glob 标准。 |
| 应用内模态列表，每页 100 项            | 原生 MessageBox 不适合展示完整长列表。分页限制一次 IPC 返回量和 DOM 行数，同时保留完整可达性。                  |

| 不增加预览期间文件变化专项             | 遵守本轮个人工具的范围约定；原同步器已有检查继续生效，不扩展为新的监控或重扫机制。                              |

## 4. 兼容约束与评审检查点

### 4.1 配置与业务范围

- 配置来源仍为开发环境 `.env`，打包后不读取 `.env`；本次没有补充打包应用的凭据管理能力。
- 空 `sync_ignore` 保持原上传范围，但仍展示新预览；清空规则不能关闭预览。
- 规则只在上传本地扫描中使用。下载、合并和 Diff 的行为与 5 MiB 文本限制保持原样；普通上传包含大文件和二进制文件。
- 单窗口刷新配置不替换其他窗口已持有的连接配置；上传任务仍使用独立 SDK 实例。
- 原有不传播删除、稳定上传快照、分片上传、临时目录归属、合并标记拦截及取消不回滚已完成文件的约定保留。

### 4.2 IPC 与内部接口

| 契约                      | 兼容要求                                                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `startOssSync(direction)` | 渲染层启动参数不变，上传确认通过新增 IPC 完成。                                                                                                                |
| `oss:sync-upload-preview` | 参数为 `taskId, offset`，返回 `OssResult<UploadPreviewPage \| null>`。仅发起窗口能取得对应待确认任务；每次最多返回 100 项。                                    |
| `oss:sync-confirm-upload` | 参数为 `taskId, decision`，decision 仅允许 `cancel / normal / overwrite-all`；成功返回 `OssResult<null>`。其他窗口、旧任务、无效值、重复确认会得到结构化错误。 |
| `SyncManager.start`       | 新增第 5 个 `ConfirmUpload` 回调。上传时必须提供，否则在取得同步占用之前报错；下载不要求该回调。旧测试夹具显式传入普通确认回调，生产代码没有自动放行默认值。   |
| `SyncState`               | 新增 `previewing` 和 `uploadMode`；`isSyncActive` 必须包括新阶段，所有状态文案也需要覆盖。每次 start 将 `uploadMode` 重置为 null。                             |
| main / preload / renderer | 新通道必须同时更新并一同构建，不能混用旧 preload 与新页面。类型检查之外，还通过真实 Electron 验证了实际 handler 注册。                                         |

继续维持三进程能力边界：SDK 和排除规则执行在主进程，preload 仅桥接具名 IPC，渲染层只接收预览路径、大小和汇总，不接触凭据或 Node 文件系统。

### 4.3 生命周期与执行顺序

- 预览时保留同步占用；同步、Diff 和在线保存的互斥不改变，其他窗口显示忙态。
- 待确认列表保存在主进程，状态广播不携带完整列表；只有发起窗口查询和提交决定。
- 确认只能消费一次。等待时取消、发起窗口销毁或关闭／退出／刷新中的取消选择，都会结束等待。
- `waitForUpload` 自身响应 AbortSignal，即使确认回调未主动响应取消，也不会无限等待；迟到决定不再启动上传。
- 普通上传内容相同检查早于修改时间确认；一键模式只绕过后者，不能绕过未整理标记检查或把失败项当成功。
- 首次预览只作范围确认，不增加本次范围外的文件变化专项。已有上传快照和身份检查继续发挥原有作用。

